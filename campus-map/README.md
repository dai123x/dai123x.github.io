# 长春工业大学 · 全景立体地图

一个零依赖、可离线运行的交互式三维校园示意模型（纯 HTML + Three.js，无需安装任何环境）。建筑与道路几何为近似可视化，不作为测绘或导航数据。

## 🚀 使用方法

**双击 `index.html`** 即可在浏览器中打开（Chrome / Edge / Firefox 均可），完全离线可用。

也可以在本目录起一个本地服务后访问，例如：

```bash
python -m http.server 8642
# 浏览器打开 http://127.0.0.1:8642/
```

## ⚡ 渲染与加载优化

本地 Chromium 复核基线（北湖校区默认场景，WebGL SwiftShader，桌面视口，加载完成后数秒采样）：约 330 Draw Calls、约 12 万三角形、约 280 个几何体；卫星底图模式下约 1 次 Draw Call。同环境下未做合批的旧版本约为 1355 Draw Calls，供参考。移动视口与桌面视口数值不同。该数据受浏览器、GPU、设备、视口和采样时点影响，不能推广为稳定 FPS 或所有场景的固定性能指标。

关键手段：
1. **静态合批**——将部分同材质道路、描边、地面与建筑组件合并为更少的网格；只对满足材质及几何条件的对象应用，需结合目标设备检查视觉效果与渲染计数。
2. **跨材质顶点色合批**——建筑内无贴图、不透明的零件按粗糙度/金属度档位合并为带顶点色的网格，档内差异控制在肉眼不可辨的范围；带贴图、半透明与夜景会发光的材质不参与。
3. **标签图集**——全部建筑名称标签打包进一张 2048² 图集，用单个 billboard 实例化批次渲染，替代数十个独立 Sprite。
4. **卫星底图图集与持久缓存**——49 张高德瓦片（影像 + 注记两层）合成为两张图集纹理、各一个网格；瓦片到达后按节流合并上传，替代原先 98 个网格与 98 张纹理。瓦片按 URL 存入 IndexedDB（影像 14 天 / 注记 3 天 TTL）：回访先绘本地缓存、过期仅后台刷新对应瓦片，二次开启卫星模式零网络请求；首访按「图集中心优先」排序、8 并发受控拉取，失败自动轮换 webst 子域重试。WebGL2 桌面端为图集启用 mipmap（连续影像无接缝），UV 半像素内缩消除瓦片边缘渗色。
5. **按需阴影**——阴影贴图仅在场景/光照/季节变化时重绘（`shadowMap.autoUpdate=false`），移动端降为 1024 分辨率。
6. **拾取加速**——每栋楼预计算包围球，点击/悬停先做射线-球粗筛再精确求交。
7. **设备分级**——移动端/低核设备自动关闭 MSAA、pixelRatio≤1.5、PCF 软阴影降档。
8. **加载节奏**——加载页先完成首帧绘制（双 `requestAnimationFrame`）后再执行同步三维构建，避免移动端长时间白屏；构建与合批耗时约 300ms（桌面）。
9. **缓存策略**——移除 `Cache-Control: no-cache` 等三条 meta（它们会让浏览器对每个子资源都重新下载），改用 `?v=` 版本号做变更失效；10 个 `<script>` 统一 `defer`，让脚本下载与 HTML 解析并行。
10. **材质分级**——仅水面、采光顶、玻璃塔等真正用到 transmission/clearcoat 的材质保留 `MeshPhysicalMaterial`；普通建筑立面一律 `MeshStandardMaterial`，外观相同但着色器开销显著更低（立面覆盖屏幕大部分像素）。
11. **rAF 看门狗**——构建入口与渲染循环均不假设 `requestAnimationFrame` 永远可用：嵌入式 WebView（应用内浏览器面板、后台节流）遮挡后 rAF 会永久停摆，boot 各跳挂定时器兜底、循环由看门狗按帧龄检测停摆并低频补帧，恢复后自动空转零开销。

## 📁 文件结构

```
index.html              入口页面（全响应式布局）
css/style.css           现代毛玻璃拟物界面样式
js/three.min.js         Three.js r128（本地离线引擎）
js/OrbitControls.js     轨道控制器（本地化）
js/campus-data.js       北湖/南湖校区的建筑、道路、导览路线与配景示意数据集
js/main.js              3D 引擎：静态合批、实例化渲染、微气候系统、智能拾取、LOD分级、截图水印导出
img/                    官方效果图/实景立面贴图（已统一转为 JPG 以压缩体积）
tools/osm_builder/      OSM 地理数据处理与构建中间工具
```

## 📚 数据来源与模型边界

模型中的楼宇轮廓、道路与校园边界参考 **OpenStreetMap (OSM) 公开空间数据**、公开校区资料及可获得的平面图进行近似示意；数据可能不完整或与现状有差异，不作为测绘、导航或建设依据。模型内个别描述所列尺寸未独立核验，不应视为精确实测值。

1. **北湖校区（西区与东区）**：模型包含教学楼、图书馆、宿舍、生活区等主要类型的示意建筑；高度、轮廓和外观均为可视化近似。
2. **南湖校区（老校区）**：模型展示主教学楼、图书馆、宿舍与运动场等主要空间元素；建筑造型与空间尺寸未进行测绘级验证。

项目目录中包含部分公开建筑效果图或实景参考素材，具体来源见下方链接；纹理只用于视觉展示，不代表模型的几何尺寸或位置已得到实地核验。
- 北湖东区各楼效果图：基建处《北湖校区东区建设项目情况简介》 https://jjc.ccut.edu.cn/info/1087/1100.htm
- 博厚图书馆实景照片：校新闻网《北湖校区迎新地标》 https://ccutnews.ccut.edu.cn/info/1027/5633.htm
- 南湖校区米黄色调与绿色坡屋顶、白色弧顶体育馆均按官方实景与鸟瞰图配色还原（无立面贴图）

## 🔧 数据再生成

建筑、道路与边界示意数据由项目根目录 `_build_real.js` 读取 `tools/osm_builder/` 下保存的公开数据源生成；树木示意点使用固定种子，重复运行可复现。输出仍是模型坐标表达，不应直接当作测绘成果：

```bash
node _build_real.js   # 重新生成 js/campus-data.js
```
